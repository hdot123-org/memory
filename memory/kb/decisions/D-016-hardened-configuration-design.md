# D-016: memory-project.toml 硬化配置设计决策记录

## 决策背景

为了进一步增强 memory-core 系统的可预测性和控制力，引入了项目级配置文件 `memory-project.toml`。这种配置方式提供了一种声明式的手段来明确指定项目的记忆根和成员仓库，作为路由逻辑的最高优先级。

## 决策内容

### 配置文件结构

```toml
# 项目身份
project = "project-name"

# 记忆根指针：唯一记忆根在 git 仓库内的位置（治理宪法不破）
memory_root = "./relative/path/to/git/repo"

# 成员仓声明（可用于消歧）
members = ["./path/to/repo1", "./path/to/repo2"]
```

### 四级路由优先级

系统按照以下优先级顺序确定项目根：

1. **git 向上归一化** - 仓库内会话，行为不变（回归保护）
2. **项目根硬化配置** - `memory-project.toml` 声明即真理（本决策内容）
3. **启发式向下探测** - 限深 1，唯一子仓库（探测逻辑）
4. **显式拒绝** - 歧义/无效，日志 + stderr 可见

### 安全保障措施

#### 路径包含检查（containment）
- 所有路径解析结果必须落在配置文件所在目录之内
- 防止 `../` 路径穿越和越界绝对指针
- 对符号链接使用 `realpath` 进行穿透检查

#### 拒绝名单
- `$HOME` 目录
- 系统目录
- memory-core 源码仓库根目录

#### 权限检查
- world-writable 配置文件（666 权限）会被降级为忽略并发出告警
- 正常权限配置（如 640）正常生效

### 冲突处理

当 git 向上归一化结果与配置声明冲突时：
- 仍然路由到 git 归一化结果（git 优先）
- 同时记录冲突日志，包含两个路径和配置文件路径
- 采用 preserve-and-escalate 策略，不静默择一

### 唯一性冲突校验

- 在目录树中检查是否存在多个配置文件的成员声明重叠
- 解析后绝对路径重叠时拒绝并列出冲突清单
- 防止多个配置文件试图管理同一个物理路径

### 配置查找范围

- 从种子目录开始，向上查找祖先目录
- 配置文件所在目录的配置优先于祖先目录的配置
- 遵循就近原则

## 影响与后果

1. **控制增强**：用户可以显式声明项目的记忆根，避免系统猜测
2. **消歧能力**：通过 members 声明可以解决多仓库的歧义情况
3. **安全性提高**：通过路径包含检查和拒绝名单防止危险路径
4. **灵活性维持**：不破坏现有的路由机制，仅作为高优先级选项

## 与其他决策的关联

- 与此决策相关的单一性硬规则：配置提供了一种明确的方式来实现单一性
- 与此决策相关的探测三分支语义：配置具有比探测更高的优先级
- 与此决策相关的 consent 过渡语义：配置文件的存在本身就表示项目所有者的意图
