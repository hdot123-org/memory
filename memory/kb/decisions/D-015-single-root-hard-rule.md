# D-015: 记忆根必须 git 治理单一性硬规则决策记录

## 决策背景

在 memory-core 系统中，为了确保一个项目对应一棵记忆树，必须建立一个硬性规则：记忆根必须是 git 仓库根目录。这个规则旨在防止类似 mencbo 事故的 split-brain 问题，即在一个项目中出现多个记忆根的情况。

## 决策内容

### 单一性硬规则定义
**一个项目 = 一个 git 治理的记忆根 = 一棵记忆树**

具体而言：
1. 每个项目必须有唯一的记忆根，且该根必须位于 git 仓库的根目录
2. 记忆根不能存在于非 git 治理的目录中（除非有显式的 consent 标记）
3. 任何布局下系统要么确定性路由到正确的 git 仓库根，要么显式拒绝，永远不静默猜错

### 无标记非 git 树处理策略
- 无标记的非 git 根被视为事故残留
- 不再作为路由目标
- 如果存在唯一有效子仓库，则路由指向该子仓库
- 这种处理方式符合单一性原则，确保最终只有一棵记忆树

### consent 标记的作用
- 通过 `memory-init --allow-non-git` 创建的记忆树会携带 `allow_non_git=true` 标记
- 有标记的非 git 项目照常服务（passthrough）
- 无标记的非 git 项目则被视为事故残留，需要重新路由到合适的 git 仓库

### 系统行为保证
1. **路由确定性**：系统要么正确路由到 git 仓库根，要么显式拒绝
2. **拒绝可见化**：所有的拒绝行为都会在 errors.log 或 stderr 中可见
3. **静默失败禁止**：系统永远不会因为不确定而静默失败或做出错误决策

## 影响与后果

1. **架构简化**：确保了记忆系统的清晰架构，避免复杂的多重记忆树管理
2. **错误预防**：防止了类似 mencbo 事故的 split-brain 问题
3. **行为一致性**：无论在何种布局下，系统的行为都是确定性的
4. **安全性增强**：防止意外在错误位置创建记忆数据

## 与其他决策的关联

- 与此决策相关的探测三分支语义：确保无标记非 git 树被正确处理
- 与此决策相关的 consent 过渡语义：允许合法非 git 项目的正常运行
- 与此决策相关的硬化配置设计：提供了声明式的方式来指定记忆根
