# 已知问题：破损 gitfile 子仓库 init 降级为目录名 scope

## 问题描述

当系统遇到破损的 `.git` 文件（非目录而是文件，通常是 worktree 或 submodule 的链接）时，初始化流程无法正常使用该 `.git` 文件来识别仓库边界和属性。此时系统会降级为仅基于目录名进行范围界定。

## 问题详情

### 触发条件
- 子目录中存在 `.git` 文件而非 `.git` 目录
- 该 `.git` 文件指向不存在或无法访问的目标
- `.git` 文件内容损坏或指向错误路径

### 行为表现
- 系统无法从破损的 `.git` 文件中获取仓库的完整信息
- 无法正确识别该子仓库的真实边界
- 无法验证该仓库的有效性
- 降级为仅将目录名作为唯一识别标识

### 当前处理方式
- 不会导致系统崩溃或错误
- 不会静默失败
- 系统会跳过该破损的子仓库，继续处理其他有效仓库
- 在日志中记录警告信息

## 影响范围

### 功能影响
- 向下探测逻辑可能会跳过破损的子仓库
- 记忆树初始化可能不会在该子仓库中创建
- 路由逻辑可能不会将该目录识别为有效仓库

### 性能影响
- 不会对系统性能产生显著影响
- 探测过程的延迟仍然在可接受范围内

## 解决方案

### 临时解决方法
- 检查并修复破损的 `.git` 文件
- 确保 `.git` 文件指向有效的目标路径
- 如不需要该子仓库，可删除破损的 `.git` 文件

### 长期解决方向
- 目前该行为被接受为可容忍的降级处理方式
- 系统的健壮性设计允许在部分子仓库不可用时继续运行
- 优先确保有效仓库的正常处理
